# 最终方案:保留现有实现(不还原)+ 内置搜索集成保护

## 结论先行

- **widget 改动保留,不还原**:全屏搜索与主站风格一致正是本次目标;`background`/`logo`/`welcome` 都是可选注入,未配置时渲染路径与改动前完全相同
- **小窗口 searchbox 安全**:`web/widgets/searchbox` 不依赖 ui-search、本次未触碰,零影响;`web/widgets/fullscreen`(独立全屏嵌入)虽引用 ui-search 构建,但可选 prop 不传即原行为,其 Logo 仍走集成自身配置
- 主站 `/#/search` 顶部已有主站导航,满足"顶部导航有一点区别/或有导航"的预期,无需新增工作

## 剩余工作:内置搜索集成(不可见 + 受保护)

`search_settings.integration` 引用的 `full-screen-widget-default` 是 setup 种子文档(`config/setup/*/misc.tpl`),现状是普通集成文档:管理列表可见、可编辑、**可删除**——误删/禁用后主站搜索(`/#/search`)直接失效。加固为内置保护:

**后端 `modules/integration/integration.go`**(新增 `core.DefaultSearchIntegrationID = "full-screen-widget-default"` 于 `core/const.go`):
1. `create`:拒绝使用保留 ID 创建(防占位冲突)
2. `delete`:内置 ID 拒绝删除(400,提示 built-in)
3. `update`:内置 ID 仍**可编辑**——它的 payload 就是站内搜索的配置面(placeholder/welcome/AI overview/深度助手);仅拒绝把 `enabled` 改为 false(防误禁)
4. `search` 管理列表:过滤掉内置文档(修正 total),对所有客户端生效——集成管理页与 IntegrationSelect 均不可见;`GET /integration/:id`(搜索页取配置的通道,允许匿名)不受影响
5. 兜底:`modules/system/init.go` 的 `RegisterAppSetting("search_settings")` 下发时,若 `integration` 为空则回落内置 ID,配置丢失搜索页仍可用
6. 新增 `modules/integration/integration_test.go`:内置判定、列表过滤、delta 守卫(纯函数单测)

前端无需改动(列表过滤在服务端完成)。
