# 后台查看文档处理进度与处理日志详情

## 现状(复用为主,增量开发)
- 单文档处理时间线 API 已有:`GET /document/:doc_id/_timeline`(status/error_message/pipeline_runs[],run 记录含 pipeline、took_ms、success、error,封顶 5 条)
- 单文档日志面板 UI 已有:`ProcessingPanel.tsx`(在 preview 页,悬浮按钮打开)
- 全局统计/失败列表/一键重试/数据源同步进度已在「检索运营」页(search-ops)

**缺口**:① run 记录没记"执行了哪些 processor";② 后台无实时队列积压/进度;③ 日志面板在后台不可达(失败列表不能点开看详情,文档抽屉里没有日志入口)。

## 后端(改动小)

**1. run 记录增加 processor 链 — `plugins/processors/process_documents/processor.go`**
- 子管道跑完后 `subCtx.GetFlowProcess()` 拿到实际执行的 processor 名单(framework 已记录,零框架改动),经 `pushEnriched` 传入 `applyProcessingOutcome`,写入 run 记录新字段 `processors: []`。passthrough 记录不带。

**2. 实时进度 — 扩展 `GET /search/ops/processing`(`modules/document/processing_ops.go`)**
- 响应加 `live` 段:`queues`(indexing_documents / documents_processed / attachment_processing 三个队列的 `queue.Depth()`,模式照 `modules/attachment/init.go`)+ `oldest_indexing`(最早一条 status=indexing 文档的 updated,卡住指示,一条 size=1 升序查询)。

## 前端

**3. ProcessingPanel 上移为公共组件**:移到 `web/src/components/ProcessingPanel/`,preview 页改 import。同时给 run 记录渲染加 `processors` 展示(Tag 列表)。

**4. 检索运营页(search-ops)增强**
- 失败列表行可点击 → Drawer 内嵌 ProcessingPanel(docId),后台直接看单文档处理日志详情;
- 「文档处理」卡片加实时进度行:三个队列积压数 + oldest_indexing + 「自动刷新」Switch(5s 轮询,默认关,useEffect+setInterval+cleanup,全仓首个轮询,新建模式)。

**5. 文档抽屉(DocumentDrawer)加「处理日志」Tab**:内容包一层 antd Tabs(内容 / 处理日志),处理日志 Tab 渲染 ProcessingPanel(data.id)。

**6. i18n**:en-us/zh-cn page.ts 的 searchOps 区块与通用 key;类型加到 search-ops.ts(照现文件模式,LiveProgress interface)。

## 不做(说明)
- per-processor 每文档耗时:需改框架 Processors.Process,收益低;run 记录带 processor 名单已能回答"哪些阶段跑了、整体多久"。

## 验证
- `go build` + 新增 run-record 单测(processors 字段);`pnpm typecheck` 无新增错误;本地起服务后:制造一个失败文档(如停 tika 后入库 pdf)→ 检索运营页看失败列表 → 点行开抽屉看处理日志(含 processor 链与错误)→ 开自动刷新观察队列积压回落。
